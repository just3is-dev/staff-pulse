# SPEC-002: Аналитическая таблица с агрегатами по подразделениям

Статус: approved <!-- draft | approved | in-progress | done -->

## Зачем

Второй этап задания ([docs/assignment.md](../assignment.md), «02 CORE»). Дерево
из SPEC-001 показывает структуру и собственные показатели узлов, но не отвечает
на аналитические вопросы: сколько людей и денег приходится на подразделение
целиком, какая у него средняя эффективность, какие подразделения крупнее или
эффективнее других. Таблица с агрегатами по поддеревьям, сортировкой и
фильтром отвечает на них, а выделение узла в дереве по клику на строку связывает
аналитику со структурой. Успех этапа — пользователь находит подразделение в
таблице, сравнивает его с другими по любому столбцу и видит, где оно в дереве.

## Что делаем

### Компоновка экрана

- На ширине окна от 1280px дерево и таблица показываются рядом, переключателя
  нет.
- На ширине меньше 1280px показывается переключатель «Дерево / Таблица» и
  только выбранный вид; по умолчанию выбрано «Дерево».
- Смена вида и переход ширины через 1280px не сбрасывают состояние:
  раскрытие ветвей дерева, сортировку, текст фильтра и выделенный узел.
- Состояния «Загрузка», «Ошибка», «Пусто» и уведомление об ошибке обновления
  из SPEC-001 относятся ко всему экрану; таблица и переключатель показываются
  только когда есть непустые данные.

### Агрегаты

Для каждого узла считаются показатели по самому узлу и всем его потомкам:

- **Всего сотрудников** — сумма `headcount` узла и всех потомков.
- **Бюджет суммарный** — сумма `budget` узла и всех потомков.
- **Средняя эффективность** — средневзвешенная по `headcount`:
  Σ(`performance` × `headcount`) / Σ `headcount` по узлу и всем потомкам.
  Если суммарная численность равна нулю, значения нет.

Агрегаты считаются один раз для каждой версии данных и переиспользуются:
сортировка, фильтр, выделение, смена вида и ревалидация без изменения данных
(ответ 304) их не пересчитывают; пересчёт происходит только когда приходят
новые данные.

### Таблица

- Плоская таблица: одна строка на каждый узел. Столбцы: «Подразделение»,
  «Уровень», «Всего сотрудников», «Бюджет суммарный», «Средняя эффективность».
- «Уровень» — глубина узла: 1 у корней, у потомка на 1 больше, чем у родителя.
- Бюджет отображается целым числом рублей с группами разрядов по три цифры,
  разделёнными пробелом, и суффиксом «руб.»: `12 345 678 руб.`.
- Средняя эффективность отображается с одним знаком после запятой
  (`72,4`); если значения нет — «—».
- Без сортировки строки идут в порядке дерева: родитель, затем его потомки
  в порядке ответа сервера, рекурсивно.

### Сортировка

- Клик по заголовку столбца сортирует таблицу по этому столбцу по возрастанию,
  двойной клик — по убыванию. Направление видно в заголовке и доступно
  вспомогательным технологиям; у остальных столбцов признака сортировки нет.
- «Подразделение» сортируется по алфавиту без учёта регистра, числовые
  столбцы — по значению.
- При равных значениях сохраняется порядок дерева. Строки без значения
  средней эффективности при сортировке по этому столбцу всегда внизу.

### Фильтр по названию

- Поле «Фильтр по названию» над таблицей. В таблице остаются строки, в
  названии которых встречается введённый текст без учёта регистра и
  окружающих пробелов; пустой фильтр показывает все строки.
- Фильтр применяется, когда с последнего изменения текста прошло 250 мс
  (дебаунс), а не на каждое нажатие.
- Фильтр не меняет агрегаты строк и сочетается с сортировкой. Если совпадений
  нет — сообщение «Ничего не найдено».
- Фильтр действует только на таблицу, дерево он не меняет.

### Выделение узла

- Клик по строке выделяет узел: строка отмечается в таблице, узел отмечается
  в дереве, свёрнутые предки узла раскрываются, дерево прокручивается к узлу.
  Выделен всегда не больше одного узла.
- На ширине меньше 1280px клик по строке дополнительно переключает вид на
  «Дерево».

### Сохранение состояния при обновлении данных

- Когда приходят новые данные с теми же `id`, сортировка, текст фильтра и
  выделенный узел сохраняются, а таблица показывает новые агрегаты.

### Документация

- `docs/data-model.md`: модель дерева (плоский список → иерархия) и алгоритм
  агрегации. Раздел о контракте live-патча дописывается на этапе 03. Пункт
  проверяется ревью, отдельного критерия приёмки у него нет.

## Границы

- Live-обновления, пересчёт агрегатов только для затронутого узла и его
  предков, подсветка обновлённых ячеек, индикатор соединения — этап 03.
- Клавиатурная навигация по таблице (стрелки, Home/End, Enter) и сортировка
  по убыванию с клавиатуры — этап 03.
- Анимация раскрытия дерева — этап 03.
- Дерево не меняется: оно по-прежнему показывает собственный `headcount`
  узла, агрегатов и цветового индикатора в таблице нет.
- Фильтр не действует на дерево; поиск по дереву не делаем.
- Выделение узла кликом в дереве, множественное выделение, сброс сортировки
  к порядку дерева через интерфейс — не делаем.
- Виртуализация строк, пагинация, экспорт таблицы — не делаем.
- AI-поиск на естественном языке — этап 04.

- [ ] AC-002-3: Функция агрегации для каждого узла возвращает сумму `headcount` и сумму `budget` по узлу и всем потомкам и средневзвешенную по `headcount` эффективность; при нулевой суммарной численности значения эффективности нет. Проверяется на наборе из нескольких корней глубиной не меньше 3, включая лист и поддерево с нулевой численностью.

## Решённые вопросы

1. На узких экранах (меньше 1280px) по умолчанию открыт вид «Дерево» (AC-002-1).
2. Средняя эффективность — один знак после запятой, пустое значение — «—»
   (AC-002-5); строки без значения — внизу при сортировке в обоих направлениях
   (AC-002-7).
3. Сортировка по убыванию с клавиатуры — этап 03, вместе с клавиатурной
   навигацией по таблице.
