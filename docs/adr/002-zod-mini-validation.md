# ADR-002: Ответ API проверяется схемами на `zod/mini` и отдельной проверкой структуры дерева

Дата: 2026-09-14
Статус: accepted

## Контекст

Клиент проверяет каждый ответ `GET /api/org-tree` до использования; невалидный
ответ — это состояние ошибки, а не частично отрисованные данные. Проверка
состоит из двух частей: форма узлов (типы полей, диапазоны, целые числа,
дата ISO 8601) и структура леса (уникальные `id`, существующие родители,
отсутствие циклов). Схема нужна и серверу — он отдаёт узлы того же типа.
Клиентская production-сборка по заданию должна укладываться в 200 КБ gzip.

## Решение

- **Форма** — схема zod в `@staff-pulse/shared`; тип `OrgNode` выводится из
  схемы (`z.infer`), так что тип и проверка не расходятся.
- **Вариант zod — `zod/mini`**, а не полный `zod`. Замер на клиентской
  сборке Vite: полный `zod` добавляет около 24 КБ gzip, `zod/mini` — около
  6 КБ при той же схеме. Семантика проверок та же, отличается API
  (функции и `.check(...)` вместо цепочек методов).
- **Структура** — отдельная функция поверх результата схемы: проход по
  `id` → проход по `parentId` → обход цепочек родителей с запоминанием узлов,
  уже доведённых до корня (O(n)). Результат `parseOrgTree` — `{ ok: true, nodes }`
  или `{ ok: false, error: { kind, message, nodeId? } }`, где
  `kind` ∈ `shape | duplicate-id | unknown-parent | cycle`.

## Альтернативы

- **Полный `zod`** — удобнее API и тексты ошибок из коробки, но в 4 раза
  дороже в бандле.
- **Ручные type guards** — без зависимости, но тип и проверка описываются
  дважды и расходятся; много кода на диапазоны и даты.
- **valibot** — сопоставим с `zod/mini` по размеру; отклонён, потому что для
  проекта заранее выбран zod, а выигрыша по размеру `zod/mini` уже даёт.
- **ArkType** — выразительный синтаксис, но крупнее в бандле и менее
  привычен.
- **Проверка структуры через `superRefine` в схеме** — смешивает форму и
  граф, теряется разделение видов ошибки (`kind`).

## Последствия

- `zod/mini` не подключает локаль с текстами ошибок: в `message` ошибки
  формы попадают путь и код нарушения (`invalid_type`, `too_small`, …).
  Текст для пользователя формирует UI, а не схема.
- `updatedAt` принимается только в UTC с `Z` (формат `Date#toISOString`);
  смещения часового пояса — ошибка формы. Сервер обязан отдавать дату в
  этом формате.
- Переход на полный `zod` при необходимости сводится к замене импорта
  `zod/mini` на `zod` в `packages/shared/src/org-node.ts`: полный `zod`
  принимает тот же функциональный API.
