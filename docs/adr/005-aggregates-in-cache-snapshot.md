# ADR-005: Агрегаты поддеревьев хранятся в снимке кэша вместе с узлами

Дата: 2026-09-15
Статус: accepted

## Контекст

SPEC-002 требует считать агрегаты по поддеревьям один раз на версию данных:
сортировка, фильтр, выделение, смена вида и ревалидация с ответом 304 не
должны пересчитывать их, новые данные — должны. На этапе 03 live-патч будет
менять отдельные узлы, и агрегаты затронутого узла и его предков нужно будет
обновлять вместе с данными. Данные клиента живут в кэше TanStack Query как
снимок `{ nodes, etag }` (ADR-004).

## Решение

Агрегаты считаются в функции запроса при ответе 200 и кладутся в тот же
снимок: `{ nodes, aggregates, etag }`. На 304 возвращается прежний снимок тем
же объектом — вместе с его агрегатами. Хук `useOrgTree` отдаёт компонентам
`{ nodes, aggregates }`.

## Альтернативы

- **`useMemo` в экране по ссылке на `nodes`** — меньше кода, но React не
  гарантирует сохранность мемоизации, расчёт привязан к жизни компонента, а
  на этапе 03 патчу пришлось бы согласовывать данные в кэше и агрегаты в
  компоненте.
- **Расчёт в `select` хука** — `select` перезапускается при смене данных и
  функции выбора, агрегаты не попадают в кэш, и патч этапа 03 не сможет
  обновить их точечно.
- **WeakMap «ссылка на `nodes` → агрегаты» вне кэша** — второй источник
  состояния рядом с кэшем, который нужно синхронизировать при патчах.

## Последствия

- Одна точка правды: узлы и агрегаты меняются вместе, одной записью в кэш.
- Контракт патча этапа 03: патч записывает в кэш новый снимок с новым
  массивом `nodes` и **новой** `Map` агрегатов — копией прежней с
  пересчитанными узлом и его предками, и с актуальным `etag`. Менять `Map`
  на месте нельзя: ссылка не изменится, и подписчики, сравнивающие по
  ссылке, обновления не увидят. Копия `Map` стоит O(N) на патч, сам
  пересчёт — O(глубина).
- Прежние агрегаты на 304 сохраняются потому, что функция запроса возвращает
  тот же объект снимка. Ответ 200 даже с тем же телом считает агрегаты
  заново: structural sharing TanStack Query сохраняет ссылку на равный
  `nodes`, но `Map` сравнивает по ссылке и заменяет. При ETag на сервере
  такой ответ редок.
- В тестах число расчётов считается шпионом, пропускающим вызов к настоящей
  функции (`apps/web/src/test/aggregation-spy.ts`, подключён в
  `test-setup.ts`).
