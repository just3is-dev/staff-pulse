# staff-pulse

Дашборд мониторинга орг-структуры компании (дивизионы → отделы → команды): интерактивное дерево и аналитическая таблица с агрегатами, live-обновления с сервера. Выполняется как тестовое задание на позицию frontend-разработчика; текст задания — [docs/assignment.md](docs/assignment.md).

## Команды (контракт agent-dev-kit)

- `./scripts/check [файлы...]` — типы + линт
- `./scripts/test` — все тесты
- `./scripts/fix [файлы...]` — автоформат

Гейты плагина зовут их автоматически после правок и перед завершением работы.
Проверка упала — чини причину. Обходить гейты (`--no-verify`, правка скриптов
контракта под задачу) запрещено.

## Стек

Монорепа на npm workspaces. Корневые `scripts/*` — диспетчер: находят пакеты
по наличию у них `scripts/check|test|fix` и маршрутизируют по путям файлов.

- `apps/web` — клиент: Vite + React + TypeScript (create-vite), oxlint, Vitest, Prettier.
- `apps/server` — mock API и live-обновления: NestJS (nest new, ESM), oxlint, Vitest, Prettier.

- `packages/shared` — `@staff-pulse/shared`: схемы и тип узла API, проверка
  ответа `GET /api/org-tree`; отдаётся исходниками TypeScript без сборки
  (ADR-001), нужен Node 22.18+.

Новый пакет обязан получить свои `scripts/check|test|fix` и попасть в
`workspaces` корневого `package.json` — корневой диспетчер подхватит его
автоматически.

## Процесс

- Фича начинается со спеки в `docs/specs/` (команда `/spec`), задачи — issues
  в GitHub (команда `/plan`), выполнение — `/work`.
- Одна задача = одна ветка = один PR. В main напрямую не коммитим.
- Неочевидные технические решения фиксируются в `docs/adr/`.
- Документы самодостаточны: читаются без других документов и истории чата.

## Специфика проекта

- Источник требований — [docs/assignment.md](docs/assignment.md). Спеки
  ссылаются на его разделы и пункты; расхождение спеки с заданием — осознанное
  решение, которое фиксируется в спеке или ADR. Оригинальный PDF лежит локально
  в `.claude/product/` и в git не хранится.
- Задание разбито на 4 этапа (01 FOUNDATION, 02 CORE, 03 POLISH, 04 BONUS).
  Один этап = одна спека = один milestone. Когда milestone этапа закрыт,
  последний коммит этапа в main помечается тегом `step/N`.
- Обязательные артефакты сдачи: README (запуск одной командой + раздел
  «AI в разработке»), `docs/architecture.md`, `docs/data-model.md`,
  `docs/adr/NNN-название.md`, unit-тест на функцию агрегации.
- UI-библиотеки (MUI, Ant и т.п.) запрещены; стилизация — без inline-CSS
  (плюсом считается styled-components).
- Бюджет production-сборки клиента — ≤200 КБ gzip.
